## Architecture
- Target: x86_64 (Intel/AMD PC)
- Machine: QEMU q35 (ICH9 southbridge)
- Firmware: OVMF (UEFI)
- Kernel: Apple XNU xnu-8796.121.2 with custom patch
- Boot: UEFI PE64 application → XNU kernel → user space
- Two modes: open (no iOS) and full (with iOS user space)

## Portability (user tanya bisa di-share ke PC teman/akun beda?)
- YES, portable. Semua script path-relative (`%~dp0`, `$MyInvocation.MyCommand.Path`), no hardcoded E:/ path di logic.
- Caveat: copy ke lokasi NTFS writable (bukan langsung dari USB FAT32/exFAT — WSL chmod +x butuh metadata).
- WSL install di PC baru butuh admin sekali (`wsl --install -d Ubuntu`).
- XNU kernel asli tetap gagal build di Linux → image loader-only (BOOTX64.EFI ada, mach_kernel kosong).

## iOS-on-x86 via emulation (user asked "port ke x86" + "tunjukan caranya pake emulasi")
- Clarified: native port of iOS user space to x86 is impossible (iOS binaries are ARM64 Mach-O, no ARM->x86 translator, closed source).
- Only way to see real iOS on x86 PC = QEMU TCG emulating ARM64 (guest ARM64, host x86). NOT a port; emulation, slow (5-20x).
- Stock QEMU cannot boot XNU; needs patched fork (example: alephsecurity/xnu-qemu-arm64).
- Wrote docs/IOS-EMULATION.md with architecture, tools, skeleton qemu cmd, risks, and comparison vs HakiOS-x86 open mode.
- User decision pending: (a) focus HakiOS-x86 open mode (x86 native, realistic boot, no iOS GUI) OR (b) explore emulated ARM64 iOS (slow, hard, not turnkey).
